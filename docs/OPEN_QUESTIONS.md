# 开放问题与调查结果

| ID | 问题 / 实测证据 | 当前处理与后续阶段 |
|---|---|---|
| OQ-001 | 三个 @earendil-works 包 1.5.0 是否可获取？ | 已解决：npm 安装成功，锁定精确版本；源码仓库为 earendil-works/pi，无需 badlogic/pi-mono fallback。 |
| OQ-002 | Windows 换行改变模板批准哈希，初跑 2 failures + 12 errors。 | 已解决：基线使用 git archive；P1 固定时钟与同一路径，对原始字节进行严格差分；静态模板快照自动核对固定提交。见 ADR-001/002。 |
| OQ-003 | 默认模型与加价系数。 | P0 暂用 Anthropic Opus 4.6 / Sonnet 4.6 / Haiku 4.5，三个 ID 及 thinkingLevel 通过 pi 目录检查。未验证真实可用性或文学效果。P3 实测后由用户决定，价格参数留空。 |
| OQ-004 | I6 新上下文与协调员持久会话如何兼容？ | P2 每轮重建 Agent，只按岗位读取矩阵重放必要会话；不得复用下游历史或将原话与干净委托同时给接收岗位。完整上下文哨兵测试在 P2，P0 仅证明两个新 Agent 不共享历史。 |
| OQ-005 | 上游creative_brief接收者不含章节情境编译员。 | 保留白名单；编译作为用户从已批准项目状态发起的独立操作，完整构思批准接线在P5。P2已有独立编译岗位和绑定projection哈希的锁定元数据格式，见ADR-003。 |
| OQ-006 | 计划称 packet 预算截断，实际源码超预算直接拒绝。 | 已明确：P1 按源码逐字节一致、超预算拒绝；不能自动截断来通过测试。见接口清单。 |
| OQ-007 | 搜索供应商尚未确定。 | P2采用可替换Tavily适配器，已按官方API实现并用注入fetch验证；未配置服务或未批准学习计划不提供工具，未调用真实服务。 |
| OQ-008 | 许可证、支付主体、部署区域、用户内容政策。 | 延用计划第14节默认假设：产品方为上游作者/获授权方；Lemon Squeezy；台港及海外华文用户；东京优先；内容不用于训练。P0 未因此创建外部服务或作出对外承诺。 |
| OQ-009 | pnpm 11 忽略旧 ignoredBuiltDependencies 配置并使 install 失败。 | 已解决：采用 allowBuilds 显式 false，安装与验证成功。未全局改变机器配置。 |
| OQ-010 | Windows CWD 锁导致整项目目录替换失败。 | 已解决：顶层本地事务持锁、备份后逐文件 rename；嵌套保存点使用临时目录。CLI 从项目目录内启动的无 Python 测试通过。强制杀进程后的本地自动恢复尚未验证；P4 采用数据库事务完成生产崩溃恢复。 |
| OQ-011 | 原始36测试中包含两个明确延后的v4.1迁移场景。 | 保持34个直接移植场景与2个旧目录保护/未提供迁移命令的范围守卫；原始Python36项另行全部运行。不宣称TS已实现旧目录分类器。见ADR-002。 |

| OQ-012 | Q8建议把编辑理由附给重写作者，但I4禁止后续岗位意见进入作者。 | I4优先；理由只给用户查看。作者重写需新的已确认资料包，不附编辑理由，见ADR-003。 |
| OQ-013 | P3商用API密钥尚未配置。 | 仅检查本项目.env或环境中的密钥是否存在，不输出值；已请用户本地配置ANTHROPIC_API_KEY。不得用faux冒充真实验证。 |
