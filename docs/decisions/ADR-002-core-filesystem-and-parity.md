# ADR-002：核心移植的字节语义、事务与验证边界

日期：2026-11-06。状态：P1 实施。

## 背景

计划要求产品运行时不依赖 Python，文件读写通过 ProjectFS；同时需与 Python 对照原始字节。Windows 的文本换行、Python 的 Unicode 长度、时间和绝对路径会影响哈希。整目录 rename 还会因工作目录被 Windows 占用而失败。原始 36 个测试含两个 v4.1 迁移检查，但该迁移脚本被计划明确排除到 P7 以后。

## 决定

- ProjectFS 的 read/readText 保留原始 UTF-8 字节/换行；领域 readText 包装按 Python universal-newline 规则读取。Python 默认文本输出随宿主平台换行；注册表状态变更和审批 pending 等显式 LF 写入保持 LF。字符预算使用 Unicode 码点，目录摘要按 pathlib 的路径组件排序（Windows 使用 lower），不使用语言地区排序。
- LocalDirFS 所有合作读写者使用同一项目级进程间锁。事务在同级临时目录执行；顶层提交持锁，先完整备份，再逐文件 rename；业务异常从备份恢复。嵌套事务使用临时目录保存点，失败可被外层捕获而不遗留修改；事务句柄在返回后失效。直接读取物理目录的其他程序不受此锁保护。
- 原先整根目录 rename 在 Windows CWD 内启动的实验出现 EBUSY，改为上述顶层逐文件提交；运行时边界测试从项目目录内启动 CLI，且从 PATH 移除 Python，验证能实际初始化。
- P1 的本地事务验证覆盖可捕获的业务/IO异常和进程间并发，不将其称为数据库级崩溃恢复。进程被强制结束可能留下锁、临时目录或备份；自动恢复和生产 worker 崩溃续跑不在当前本地模拟的已验证范围。P4 以 PostgresFS 事务及任务检查点完成生产恢复测试。
- 生成只读 upstream-bundle.json：从固定 vendor Git 对象提取 24 个模板文件原始字节、作者核心来源及正则规则；模板以 base64 保留字节。运行时直接导入该快照，通过 ProjectFS 写项目，不调用 Git/Python。开发脚本 `scripts/sync-core-assets.py --check` 自动核对固定提交，不在测试中重写快照。
- Python 与 TS 差分使用同一绝对项目路径顺序运行，每步恢复共同起始字节；固定时钟，仅在测试适配器中替换 datetime/Date；运行未修改的上游函数/CLI，严格比较退出码、JSON 结构及所有文件原始字节，不删时间字段或跳过哈希字段。
- 上游没有 reserve/commit/rollback CLI，测试适配器分别调用两边真实库接口，统一外层结果字段命名；产品 CLI 不虚构上游子命令。
- 36 个同名 Vitest 场景保留映射。34 项直接测试移植模块；两个 legacy 场景测试拒绝覆盖非空旧目录、拒绝未提供的迁移命令且源文件不变；原始 Python 36 项仍全部独立执行。没有把旧目录迁移实现夹入运行时，也不宣称 TS 已实现 v4.1 分类器。

## 预览与记忆提交

新增显式 createMemoryPreview/commitMemoryPreview 核心接口，以落实 I9：预览只写报告；批准事件绑定整个预览；提交前重新检查注册表与各文件基准哈希；文件、注册表、审计、状态和审批消费都处于同一 ProjectFS 事务。

当前接口仅修改已经 active 的人物/世界/故事资源，拒绝表现能力修改。表现能力继续要求新版本、闭合审计与非正典试写。已批准预览精确绑定所有修改字节；提交内为这些已批准资源生成确定性派生 resource_activate 事件并消费，使更新后的注册表继续满足上游对目标哈希批准证据的要求。父 memory_commit 事件和审批历史保留用户对整份预览的批准证据，派生 ID 绑定父事件 ID、资源 ID 和新哈希。

## 替代方案

不采用运行时调用 Python、跳过哈希/时间字段的“近似差分”、Windows 强制全局 LF、修改 vendor、放宽表现资源证据或复用已消费事件。PostgresFS 留给 P4，当前不引入数据库/付费服务。
