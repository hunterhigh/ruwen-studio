# ADR-003：岗位输入边界与本地章节批准流程

日期：2026-11-06。适用于P2。

2026-11-09审查补记在本文件末尾；其中明确覆盖以下历史装配和记忆预装决定。岗位隔离及人工批准不变量保持有效。

## 背景

pi 1.5.0默认工具校验可能转换参数类型，混合工具批次也不能仅凭某个工具的terminate保证后续工具不执行。上游没有为全部12岗位定义产品级JSON schema；同时，计划的编译员路由、作者重写提示与上游交接白名单及I4存在措辞差异。

## 决定

- 每次runRole新建Agent。系统只装载本岗位文件与必要的灵魂/通讯契约片段；输入构造器按字段挑选。作者无工具，只接收已编译资料包；读者只收到正文、章节号和最多600码点的前章尾部。
- beforeToolCall在pi执行前对原始参数作不转换类型的schema检查；工具批次顺序执行，成功提交后阻断剩余调用。结构化输出缺失/非法最多纠正一次，finishTurn统一限制总轮数。中止、超时和供应商错误保留实际已报告用量。
- 岗位资源读取校验注册表、active/approved、project作用域、readers和原始字节哈希。文件读取后立即对同一份字节验哈希，避免先验哈希后读取的窗口。没有写文件、任意路径读取或执行工具。编辑诊断最多2次；顾问搜索需显式批准学习计划和已配置搜索实现，最多3次。
- 采用Tavily可替换适配器，按[官方Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)实现POST/Bearer，结果有长度和URL约束。未使用真实搜索密钥或调用服务。
- 编排固定作者→读者→编辑→情节核验→现实核验；通过后等待候选稿批准，再生成记忆预览并等待第二次批准。事务内重读状态和哈希，候选稿还绑定本次实际使用的资料包。记忆补丁不得越出该岗位读取过的资源快照。
- 只有明确锁定事件和顺序进入情节核验；不把普通描述自动提升为必须发生的事件。支持与projection哈希绑定的`.promises.json`旁文件，缺失时锁定列表为空。P5编译预览获批后写入此元数据；本地受信调用者也可显式提供锁定数组。
- RESTAGE理由供用户查看，不能直接交给作者。重新写作必须从重新确认的作者资料包开始，保持I4；不实现“把编辑意见附在作者输入里”的默认建议。
- creative_brief保持上游允许的接收岗位。章节情境编译作为用户对已批准项目状态发起的明确操作；P2只实现岗位与本地章节链，完整构思委托批准/分派接线属于P5，不扩宽交接schema。

## 边界与替代方案

没有采用全岗位提示词包、复用Agent历史、工具自动写文件或自动批准候选稿。本地运行记录和提示词保存在项目reports目录；数据库索引、worker检查点、幂等续跑和进程崩溃恢复在P4。P2不宣称本地记录已等同于生产队列。

取消在候选稿批准前不产生正式章节。若候选稿已经批准，中止记忆岗位仍保留已批准章节和pending_consolidation，不自动撤销用户批准，也不自动协调记忆；恢复该停点的产品入口属于P4/P5，当前可使用受控core预览/协调接口处理。

## 2026-11-09 · A1人类定案

十个非作者/非读者岗位按固定顺序完整载入所属SKILL、CREATIVE-SOUL、information-contract、creative-communication-contract、该技能全部非roles/diagnostics参考文件和自身岗位文件。只把CRLF/CR统一为LF，不trim、不摘录、不重写，frontmatter保留；其他岗位文件不载入。完整上游原文位于最前、系统前缀稳定，末尾追加固定的平台执行附注和岗位输出格式。原文中的脚本/批准/岗位调用由平台负责，模型没有因此获得额外工具。

作者/读者遵守SKILL的特殊隔离：作者仅自身岗位文件及既有AUTHOR_CORE系统片段、用户消息为编译资料包；作者核心按本次人类特别要求在系统和资料包各出现一次，不去重。读者无SOUL/SKILL/shared/通用references。文学编辑移除brief，只收正文、读者反应和按需诊断；现实核验材料不扩大。

记忆边界以人类对OQ-016的回复为准：SKILL记忆段落规定“先生成变更预览”，清单里的预览是岗位产出；shared明确允许权威资料。只预装批准正文和id/path/type/scope/sha256元数据，按需读取继续受readers约束。readResources记录本次读取快照，补丁只能绑定实际读取哈希；不得预装未批准候选及其推断。不是把资源正文改名为预览。

runRole显式传cacheRetention=long。已安装pi-ai 1.5.0的anthropic-messages会给原始系统块加ephemeral cache_control，支持长缓存的模型再加1h TTL；记录实际usage而不宣称每次必定命中缓存。新增0002迁移/Drizzle列cache_read_tokens和cache_write_tokens，保留完整usage JSON；迁移器改为顺序执行新增迁移，不修改已应用0001。

测试：12岗快照、原文完整子串/顺序/自身岗位末位、他岗和诊断排除、作者读者源文排除、SKILL材料白名单/双重输入、作者核心双份、实际缓存选项和前缀稳定；原隔离哨兵保留。记忆测试覆盖未批准输入、元数据不含正文、正确哈希但未读取仍拒绝；worker测试验证缓存计数实际落库及迁移幂等。覆盖原SKILL作者预算/候选不入Canon的核心不变量测试仍运行。

## 2026-11-09 · A3正文格式

保留A1字段白名单，正文、批准正文、上一章尾部、当前用户表达等文本使用带标签的分段原文，不再把整章编码为JSON字符串。读者反应按定位/类型/反应原文分段，保留每条文本内换行。锁定事件、硬设定、作用域等结构化资料仍可使用JSON。作者消息仍为编译资料包原文。

段落标签附字段名和码点长度，让faux/调试读取遇到正文自带闭合标签时仍能完整复原；这不是扩大模型读取范围，也不把文本标签当作权限控制。测试覆盖原始换行/引号/emoji、标签碰撞、结构化值及编辑/核验字段隔离，原有完整上下文哨兵继续运行。

完整检查首次遇到Windows并行快照/fsync引发的旧测试初始化超时，Vitest限制为2个并行测试文件；保持原有超时与全部断言，不降低隔离或批准要求。
