# ADR-003：岗位输入边界与本地章节批准流程

日期：2026-11-06。适用于P2。

## 背景

pi 1.5.0默认工具校验可能转换参数类型，混合工具批次也不能仅凭某个工具的terminate保证后续工具不执行。上游没有为全部12岗位定义产品级JSON schema；同时，计划的编译员路由、作者重写提示与上游交接白名单及I4存在措辞差异。

## 决定

- 每次runRole新建Agent。系统只装载本岗位文件与必要的灵魂/通讯契约片段；输入构造器按字段挑选。作者无工具，只接收已编译资料包；读者只收到正文、章节号和最多600码点的前章尾部。
- beforeToolCall在pi执行前对原始参数作不转换类型的schema检查；工具批次顺序执行，成功提交后阻断剩余调用。结构化输出缺失/非法最多纠正一次，finishTurn统一限制总轮数。中止、超时和供应商错误保留实际已报告用量。
- 岗位资源读取校验注册表、active/approved、project作用域、readers和原始字节哈希。文件读取后立即对同一份字节验哈希，避免先验哈希后读取的窗口。没有写文件、任意路径读取或执行工具。编辑诊断最多2次；顾问搜索需显式批准学习计划和已配置搜索实现，最多3次。
- 采用Tavily可替换适配器，按[官方Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)实现POST/Bearer，结果有长度和URL约束。未使用真实搜索密钥或调用服务。
- 编排固定作者→读者→编辑→情节核验→现实核验；通过后等待候选稿批准，再生成记忆预览并等待第二次批准。事务内重读状态和哈希，候选稿还绑定本次实际使用的资料包。记忆补丁不得越出该岗位读取过的资源快照。
- 只有明确锁定事件和顺序进入情节核验；不把普通描述自动提升为必须发生的事件。支持与projection哈希绑定的`.promises.json`旁文件，缺失时锁定列表为空。P5编译预览获批后写入此元数据；本地受信调用者也可显式提供锁定数组。
- RESTAGE理由供用户查看，不能直接交给作者。重新写作必须从重新确认的作者资料包开始，保持I4；不实现“把编辑意见附在作者输入里”的默认建议。
- creative_brief保持上游允许的接收岗位。章节情境编译作为用户对已批准项目状态发起的明确操作；P2只实现岗位与本地章节链，完整构思委托批准/分派接线属于P5，不扩宽交接schema。

## 边界与替代方案

没有采用全岗位提示词包、复用Agent历史、工具自动写文件或自动批准候选稿。本地运行记录和提示词保存在项目reports目录；数据库索引、worker检查点、幂等续跑和进程崩溃恢复在P4。P2不宣称本地记录已等同于生产队列。

取消在候选稿批准前不产生正式章节。若候选稿已经批准，中止记忆岗位仍保留已批准章节和pending_consolidation，不自动撤销用户批准，也不自动协调记忆；恢复该停点的产品入口属于P4/P5，当前可使用受控core预览/协调接口处理。
