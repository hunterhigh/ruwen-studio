# ADR-005：数据库事务、岗位结果与任务恢复

日期：2026-11-09。适用P4，P3延期依据见ADR-004。

## 持久化与隔离

使用pg 8.23.1、Drizzle 0.45.4、pg-boss 12.38.1。Drizzle导出18张业务表，SQL迁移另包含历史/账本触发器；迁移采用哈希校验和事务锁，不能修改已经应用的迁移。认证表仅提供基础字段，Better Auth接线属于P5；额度和支付表不代表P6已经启用。

PostgresFS每次操作先锁定并核对项目所属用户；同项目事务串行、嵌套使用SAVEPOINT、独占创建使用主键冲突保护。content存bytea，sha256和size由数据库根据原始字节生成。历史版本与原修改同事务提交或回滚。事务内并发读取进入同一SQL序列，避免在单连接上同时发起query。

文件形式的批准事件和消费标记仍为权威数据。approval_events仅为索引，与文件写入/消费一起提交。PostgresFS的displayPath采用项目相对路径，让闭合证据导出后仍可用；root仍含项目UUID，用于运行隔离。

## 队列与检查点

[pg-boss按至少一次投递](https://pgboss.io/introduction)，所以队列重投是正常恢复路径。运行创建/审批请求与入队使用同一数据库事务；每个项目的worker任务持有会话级advisory lock，但不把数据库事务横跨模型调用。

步骤状态、项目文件和批准消费在短事务内落盘；进度只发项目ID、运行ID和状态，不放正文。[PostgreSQL NOTIFY在事务提交后交付](https://www.postgresql.org/docs/current/sql-notify.html)，断线客户端应重新查询pipeline_steps，不能把通知当作权威状态。

每个run/role有唯一调用记录。调用前保存输入哈希、模型和提示词引用，完成后同事务保存结果、transcript、用量与唯一role_cost_events。重投复用已经完成的结果，不再次请求模型。实际点数扣款在P6；P4只保证报告费用事实去重，不声称已经接入付费账户。

恢复章节时沿原run ID重放确定性步骤，已完成的检查点不会倒退，资料包字节和请求哈希必须匹配；模型调用由持久结果仓库复用。候选稿批准单独提交后才入队记忆岗位，记忆预览可从已存在且仍匹配的预览继续；记忆批准与协调、文件/注册表/账本和最终状态同事务提交。

默认没有文学重写或模型失败自动循环。基础设施重投上限5次用于进程故障；running但无结果的模型记录不会因此重新调用。队列失联检测同时设置supervise/monitor周期；只设置supervise会受默认monitor间隔限制。生产默认心跳20秒、monitor 5秒；测试心跳10秒。

## 无法混同的两个边界

已保存的岗位结果可以安全复用。若进程在服务商收到请求后、结果持久化前被杀，数据库不能确认外部请求是否完成、是否收费；不能靠重发来声称“恰好一次”。此时自动恢复停止，运行标为FAILED并明确提示unknown provider outcome，岗位费用保持NULL而不是伪造0；需人工核对后作新的明确决定。P3真实验证和P6预留/结算必须保留这个边界。

P4验证杀死14个状态事务和6个岗位结果保存点后能继续，另验证作者/记忆请求结果未知时不会重发。没有把faux实验推断为真实API的请求幂等保证。

## 测试环境与归档

本机没有Docker，采用固定版本embedded-postgres启动真实Postgres，限定127.0.0.1、随机端口和临时数据目录；不创建操作系统用户。相比引入模拟数据库，它保留了真实事务、锁、触发器、NOTIFY及pg-boss行为。另提供compose.yaml；Docker运行路径本机未实测，CI可通过TEST_DATABASE_URL使用名为ruwen_test的测试库。生产部署仍使用外部托管Postgres，内嵌二进制不是生产依赖。

归档使用yazl/yauzl和Node CRC32校验，保留逐文件原始字节，不为导入重写批准哈希。限制压缩包32MiB、展开128MiB、单文件16MiB、条目10000个；拒绝逃逸路径、符号链接/特殊文件、加密包、重复及大小写/Unicode规范化冲突、CRC错误。先完整验证再在空项目事务内导入，失败不留下部分文件。

格式化排除fixtures和.local：这些目录的JSON包含哈希约束，不能按代码样式重写。

## P3 花园稿编辑范围修正（2026-11-13）

实测旧双边界保留了不应保留的半句与引号，并把 replacement 中的动作和右边界再次拼接。人类决定改为 `{original,replacement,kind,reason}`：original 必须非空、在同一作者原稿中逐字唯一；代码整段替换。保留单项1600码点、总量15%及重叠范围拒绝；正文和引号是否纳入操作由完整 original 明确表达，不猜测作者意图。

拒绝新引入的相邻重复片段（至少6个非空白码点），以及 replacement 开头/末尾复制已保留的左右邻文（至少6码点）；逐条给出错误位置、重复原文及修正说明，沿用一次格式纠正。作者原有重复不因其他修改而被拒绝。旧缓存中双边界格式失败关闭，不能自动猜测迁移为新格式；已有候选稿和报告不追写，需新运行。平台附注、提交 schema 与确定性应用同时切换，上游原文不变。
