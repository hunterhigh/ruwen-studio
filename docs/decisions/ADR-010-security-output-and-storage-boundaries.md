# ADR-010：S0 安全输出与平台资料边界

日期：2026-11-09。依据：人类提供并要求实施的 SECURITY-DESIGN 第 3–5 节。I1–I13 与上游提示词不变。

项目只保留 prompt_sha256 与允许的岗位结果字段。生产 worker 将实际系统原文交给 prompts 表；无数据库的本地 CLI 不保存原文。数据库迁移也清理平台运行报告的历史副本，避免文件历史成为第二个泄露点；正典和批准/审计数据不变。归档遇到未迁移内部资料时失败，不静默漏掉文件。

30 字检测遵守设计 3.3 的用户材料豁免。作者核心按先前人类定案同时存在于系统和资料包；因此不能把用户原已持有的资料或公开上游原文一律判为泄露。金丝雀不享有此豁免。

S0 先采用保守的整次岗位 delta 缓存：验证完成后再发布原始事件块，防止跨块、跨轮、字段及正规化后的泄露在检查前出现在网页。这增加流式首字延迟，但不扩大上下文或工具权限，不影响批准门。后续若改为有界延迟窗口，须证明跨字符/正规化边界同样安全；当前不以体验为由提前发布未经检测的文本。

检测事件只含元数据，每次计 1 分；幂等事件与用量、结果共同持久化。S1-4 再决定冻结与管理流程，本次不推断生产风控阈值或自动封禁。

录制也遵守相同边界：v2 录制只保存系统消息的哈希引用，正常用户请求、响应与 usage 保留；泄露响应在写录制文件前替换，原始响应用于本次安全判定但不落盘。旧 v1 录制拒绝回放，避免重新暴露旧原文。录制目录必须在用户项目之外，0600 且不入 Git。此处以安全设计替代 ADR-008“完整请求”对系统全文的旧要求；正常响应的 record/replay 仍精确复现并校验请求哈希。
