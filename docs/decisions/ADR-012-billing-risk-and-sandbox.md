# ADR-012：P6计费事务、风险复核与沙箱边界

2026-11-10。人类重新分工：主线程负责billing、支付和风险冻结，可在等待构思4批后端PR时先做P6；P5未被视为完成，不自动进入P7/P3。构思、.github、v4.1迁移仍由并行线程负责。主线程使用0103–0105迁移，对方批次1使用0200。

## 决定

1. 余额始终由只追加账本求和，不再维护可覆写的余额缓存。账户行锁串行化预留、结算、充值和风险复核。预留与pipeline_runs/pg-boss同事务；任务入队失败或返回空ID全部回滚。尚未受理的拒绝不产生失败占位任务。
2. 预留保存本次加价倍数与每美元点数快照。每个role_run使用实际usage数组的cost.total求和，以Postgres numeric乘配置并ceil为整数点；role结果、成本事件和只追加扣点同事务，引用唯一键抵抗重放/崩溃。实际成本不截断为预留值；可用预算耗尽时阻止后续模型调用，P3需校准预留。
3. 正式与沙箱为两个独立账本bank。real/record使用正式点，faux/replay只消耗沙箱点；测试支付只能增加沙箱点，不能为正式模型付费。注册赠点在用户插入事务中触发，启动时仅为老用户补一次赠点，不追溯扣历史运行费用。
4. 终态释放已核实剩余预留；有服务商结果未知的role intent时标为review并保留，未知用量不是0。0105增加usage_unknown：服务商错误/中止未完整返回usage，或完全没有usage时成本NULL并显式待核对；已报告的部分usage仍按实际值结算一次，未知部分不造零。已批准正文不因取消或费用处理撤销。人工核对未知结果的运营界面尚不在本次实现。
5. 风险事件在同一事务的触发器中累计，达阈值冻结后续模型运行；越权只计入发起请求的已认证账户，不按受害邮箱冻结他人。人工解冻保留所有事件，用reviewed_score记录复核基线；新事件仍可再次冻结。冻结、解冻审计只追加，管理员须CSRF、明确复核及陈旧状态校验。
6. 收费关闭与faux验证分开。BILLING_DISABLED只拦依赖收费开启的正式付费功能，试用/非付费与faux不因真实收费默认关闭而全部停用。正式付费身份从服务端订阅或正式充值账本识别，不从JSON接受paid标记。排队后实际模型调用前再次检查，拒绝不产生新调用或扣点，并释放可核实的剩余预留。
7. PaymentProvider当前围绕点数包结账和签名后的事件验证设计；verifyWebhook同时解析为受限事件，避免业务层误用未验签的parse结果。Mock只在本机非生产预览开放；Lemon Squeezy强制test_mode，校验store/variant/币种/金额/支付状态。服务端结账快照决定点数，custom_data只有不可猜的checkout_id。事件ID/订单ID唯一约束与同事务入账保证只加点一次。未启用真实订阅、真实退款或自动发票门户，不把测试包命名为已上线月订阅。

## 时间戳与外部协议

官方说明签名位于X-Signature、签名对象是原始请求体，事件携带订单资源及custom_data：[请求格式](https://docs.lemonsqueezy.com/help/webhooks/webhook-requests)、[验签](https://docs.lemonsqueezy.com/help/webhooks/signing-requests)。适配器不发明未被协议签名的timestamp头；使用签名体中的订单updated_at检查配置化±300秒窗口。过期/未来通知拒绝入账，延迟的合法投递需人工核对；本阶段未提供自动补单。订单金额/variant以[订单对象](https://docs.lemonsqueezy.com/api/orders/the-order-object)字段为准；创建测试结账遵循[checkout API](https://docs.lemonsqueezy.com/api/checkouts/create-checkout)。

## 占位参数与未决点

赠点暂为250000点/每bank，章节预留100000点，目的是本机可同时预留两次章节；实际扣点仍按已发生usage，不把预留当售价。两种一次性测试包、汇率、加价、预留、阈值和时限都在配置或明确的部署环境中，统一标注待P3实测。生产默认不开放沙箱购买且真实收费关闭，P3通过也不自动开启收费。

S1-4本次落实风险冻结/人工复核及账本；设计中的会话频率、一次性邮箱名单、用户可调每日上限尚未完成，不宣称整个3.5已执行。真实Lemon商店/key/外部投递未由本次代码或本地签名样本替代验收。I1–I13、上游原文与vendor不变。

## 2026-11-11人类修正：费用确定性与人工核对

第4条的“服务商错误即未知”由本决定替代：每次模型请求独立跟踪生成证据。HTTP/过载/拒绝、未收到内容即失败，以及本地调用前校验失败属于已知零费用；既有完整请求的usage仍保留。只有开始生成后断线/中止、强杀未落盘或结果不明才usage_unknown。不以安全层onDelta是否已放行为计费证据，因为生成的thinking和被暂扣文字也可能收费；该生成标记仅为内部布尔元数据，原始文本不落盘/SSE。

0106新增只追加credit_reservation_reviews。管理员在统一资源守卫、角色与CSRF校验后填写理由，按受理时费率把核实的运行总USD费用换算点数，用追加差额修正已结算金额；释放只释放剩余预留，不撤销已核实用量。账户锁、状态/remaining校验和reservation唯一审计使重放/并发只处理一次，账本/预留/理由/管理审计同事务。原始岗位未知标记保留，用户同时看到运行已人工核对的说明。真实收费、I1–I13和人类批准门不变。

## 2026-11-11：人类亲自启动的 DeepSeek 本机试用

人类授权新增唯一例外：`pnpm preview:real` 在非生产、本机 HTTPS 3001、独立 55329/ruwen_real_preview 数据库中，以 `MODEL_MODE=real` 和 `MODEL_PROFILE=deepseek` 使用赠送沙箱点数记录真实 usage。正式部署的 real/record 仍使用正式点数。章节、构思及记忆预览统一通过 `currentBank` 选择，沿用预留、逐岗位结算、未知费用核对与风险限制；不增加充值、实际收款或自动补点。

该例外须同时满足专用数据库、URL、Cookie 前缀、禁读环境文件、关闭支付和非生产等边界；错误配置拒绝执行。赠点仍为配置中的 250000 点。提供商预付余额承担实际模型费用，沙箱点数不是提供商余额，也不构成额外 USD 硬上限。P3、定价和公开收费闸门保持未通过。

key 由人类在 PowerShell 的进程环境中提供；启动器复用共享凭据策略及 DeepSeek 路由，不另建凭据来源。web/worker 继承同一环境，数据库子进程不继承 DeepSeek key。启动器不载入 `.env`，不接受 key 参数、不记录原始服务输出；认证随机数及 TLS 证书与模型 key 分开。开发与浏览器验收只执行显式 `--faux` 演练，真实启动由人类执行。原 3000 预览与数据库保持运行。
