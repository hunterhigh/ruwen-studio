# ADR-019 · 候选版本审计与重核验

状态为已确认。块 E 的预检表明，上游治理检查要求项目审计字段与白名单完全一致，PLAN 的 I11 要求明确核验失败后退回上游。

一次保存的事务会创建不可覆盖的候选文件、更新运行的版本引用、追加两条审计记录。平台的 `candidate_revision_audit` 记录操作者、运行、版本、前后哈希、改动字数与操作。它通过触发器保护追加语义，独立于可删除的业务数据。ZIP 保留候选文件和项目账本的白名单摘要。字数按去除共用前缀、后缀后较长一侧的 Unicode 码点计算。

重核验使用独立任务、预留和角色调用记录，绑定候选版本与正文哈希。任务只调用情节和现实核验员，以旧有计费逻辑扣除实际用量。两个核验均通过时更新核验基准并继续等批准。若当前版本有明确失败，按 I11 退回章节情境编译。版本更新会让前一任务的结论失效，服务端按最终可确认的用量结算。

重核验的预留沿用现有同量级配置的 25,000 点暂定值，随 P3 一起校准。用户在现有收费闸门内发起任务。
