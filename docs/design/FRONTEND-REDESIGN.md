# 如文工作室 · 前端改版指令包（交给 Codex）

> 版本：v1（2026-11-17）
> 适用仓库：hunterhigh/ruwen-studio（基线 6d129b6），只改 `apps/web` 的前端。
> 视觉依据：`docs/design/ruwen-studio-redesign.html`（单文件原型，浏览器直接打开；侧栏底部"设计规范"页是颜色、字体、组件和用词的权威来源）。
> 用法：先把原型和本文件放进仓库（见下方"准备"），然后**按顺序**每次把一个指令块完整粘贴给 Codex。一个块对应一个分支、一个 PR。

1. 把 `ruwen-studio-redesign.html` 放到仓库 `docs/design/ruwen-studio-redesign.html`。

## 块 0 · 总则

```text
你在 hunterhigh/ruwen-studio 仓库工作。接下来会分 11 个块给你前端改版任务，本块只建立规则，不写功能代码。

先完整阅读：
- docs/design/FRONTEND-REDESIGN.md（本指令包全文）
- docs/design/ruwen-studio-redesign.html（用浏览器打开，逐页点一遍；"设计规范"页是权威）
- docs/PLAN.md 第 2、9 节；docs/security/SECURITY-DESIGN.md 第 3.3、3.4 节
- apps/web/src 下全部组件与 public/studio.css

然后把下面的规则写进 apps/web/AGENTS.md（新建或追加"前端改版规则"一节），以后每个块都必须遵守：

1. 范围：只改前端。允许改 apps/web/src/components/**、apps/web/src/app/**/page.tsx 与 layout.tsx、apps/web/public/**、新建 apps/web/src/copy/**、apps/web/src/ui/**、apps/web/e2e/**。
   禁止改：packages/**、apps/worker/**、数据库与迁移、apps/web/src/server/**（只读使用）、任何 API 路由的请求或响应格式。
   如果设计需要的数据现有 API 没有提供：界面降级（隐藏该元素或显示通用文字），并在 docs/OPEN_QUESTIONS.md 记一条"前端改版缺数据"，不要自己加接口。
2. 视觉依据：原型的颜色、字号、间距、组件和用词以"设计规范"页为准。原型里的数据是演示数据，实现时一律用真实 API 数据。
3. CSP（apps/web/src/server/security.ts 已是 style-src 'self' 'nonce-…'、img-src 'self'、font-src 'self'）：
   - 服务端渲染的 HTML 里不得出现 style 属性；需要动态定位的（如页边批注的 top）在客户端 useLayoutEffect 里通过 ref 设置 element.style。
   - 不使用 data: 图片和 data: 字体，不引用任何外部资源。字体文件放 public/fonts 自托管。
4. 安全渲染不变：所有模型输出和用户内容继续经过 SafeMarkdown；禁止 dangerouslySetInnerHTML；不渲染外部图片。
5. 批准语义不变：所有批准请求照旧携带 expectedSha256 / expectedTargetSha256 等字段；界面上的"阅读门槛"只是增加的前端约束，服务端仍是权威。不得自动批准、自动重试或自动重跑。
6. 文案：所有界面文字放 apps/web/src/copy/zh-CN.ts，组件里不写死中文（测试文件除外）。状态、反应类型、编辑决定等内部值一律经过用词表转换后显示。
7. 用户页面不显示：美元金额、模型名、token 数、缓存命中、内部枚举值、原始 JSON、文件哈希（哈希可放在折叠的"技术信息"里）。管理后台不受此限制。
8. 不使用 window.confirm / window.alert / window.prompt，统一用块 1 的 ConfirmDialog。
9. 只做桌面网页，最小宽度 1180px，不做平板和手机适配。
10. 不新增 npm 运行时依赖。如确有必要（例如字体分包工具只在构建前离线运行一次），写 ADR 说明，且产物提交进仓库，运行时不依赖它。
11. 每个块完成时：pnpm lint && pnpm typecheck && pnpm test 全绿；pnpm test:e2e 全绿（选择器随改版更新，保留 data-testid="run-status" 与 "ideation-stream"）；用 Playwright 在 1440×900 下给本块涉及的每个页面和关键状态截图，存到 docs/reports/frontend-redesign/<块号>/，并写 docs/reports/frontend-redesign/<块号>.md：做了什么、与原型的差异及理由、新增的 OPEN_QUESTIONS。
12. 一个块一个分支一个 PR，PR 描述贴截图列表。不要把多个块合并做。

本块交付：AGENTS.md 更新 + 一份 docs/reports/frontend-redesign/00-inventory.md，列出现有每个页面、每个按钮/链接/表单目前调用的 API 与数据字段（后续块会用到）。不写功能代码。
```

## 块 3 · 章节审稿桌

```text
任务：按原型"章节写作"页重写 apps/web/src/components/ChapterStudio.tsx（可以拆成多个文件放 components/chapter/）。这是整个改版最重要的一页，原型里每个可点的地方都要做出来，原型里只弹提示的地方按下面的说明设计。

数据来源（全部是现有 API，不改后端）：
- GET /api/projects/:id/runs → 运行列表；GET /api/runs/:runId → 运行详情（run.status、chapter、candidateSha256、memoryPreviewSha256、targetBeforeSha256、returnReason、error；prose、original、factChanges、literaryChanges、reports[岗位].output、roles[]、memoryPreview、memoryFiles[]）；GET /api/runs/:runId/events → SSE（delta、reset、status）。
- 每个岗位的点数：GET /api/account 的用量列表里有 run_id、role_id、charged_credits，按 run_id 过滤后按岗位求和。没有对应记录时显示"用量待核对"。不显示美元。
- 编辑器输出格式：先阅读 packages/agents 中 wenxue-bianji 的提交 schema 和 packages/core/src/text-edits.ts，确认锚点替换操作的字段，再实现修订稿。

A. 页面头部
- 标题：宋体 26px"第 N 章"；如果正文里能取到章题（首行"第一章　XX"），显示为"第 1 章 · 换马"，取不到只显示"第 N 章"。
- 下方一行：StatusBadge（用 zh-CN.ts 的 runStatus）+ 小字"已用 X 点 · 完成时间"。
- 右侧"运行记录"：横向排列本章所有运行（第 3 次 / 第 2 次 · 已退回 / 第 1 次 · 已放弃），当前选中的为纸白描边。点击其他运行：以只读方式打开那次运行（没有批准栏），顶部显示一条说明"这是第 2 次运行，已于 X 退回。退回原因：……"。运行超过 5 次时，后面的折叠进"更早的运行"下拉。
- 最右"写新的一章"按钮：打开对话框（不是页面跳转）——
  · 字段：章节号（数字，默认 = 已有最大章节号 + 1；如果当前章还没 DONE，默认当前章号并在下方提示"第 N 章还有未完成的运行"）。
  · 仅当 /api/settings 返回 scenarios 非空（开发预览）时，额外显示"模拟场景"下拉。
  · 按钮"开始写作"。提交 POST /api/projects/:id/chapters。
  · 失败时在对话框里显示错误，不关闭：FAILED_PRECONDITION →"写作前的资料还不完整"+ 按钮"去项目概览查看"；INSUFFICIENT_CREDITS →"点数不足或今日额度已用完"+ 按钮"去账户与用量"；其他错误显示 errorCopy 对应文字。
  · 成功后关闭对话框，切换到新运行。

B. 岗位链（6 个节点横排，中间一条细线）
- 节点状态：等待（虚线圆圈，小字"等待"）、运行中（岗位色圆圈 + 缓慢呼吸动效，小字"正在写"/"正在读"/"正在核验"；尊重 prefers-reduced-motion）、完成（岗位色浅底 + ✓，小字点数）、失败（--seal-deep 圆圈 + ！，小字"未完成"）。记忆维护在正文批准前小字"正文批准后开始"。
- 点击节点弹出"它看到了什么"浮层（再点或点外部关闭），内容为固定文案（放 zh-CN.ts），按原型：
  · 小说作者 — 看到：作者资料包（章节情境、项目声音、POV 镜头、硬设定摘录）；没看到：人物全档、世界资料、故事大纲、研究资料、其他岗位的意见。
  · 情感读者 — 看到：作者原稿正文、上一章结尾；没看到：大纲、章节情境、检查表。
  · 文学编辑 — 看到：作者原稿、读者反应、按需加载的诊断（如果 reports 里能取到加载过的诊断名就列出）；没看到：大纲和项目资料原文。
  · 情节核验员 — 看到：编辑后的正文、本章必须发生的事件；没看到：读者反应和编辑意见。
  · 现实核验员 — 看到：编辑后的正文、硬设定规则；没看到：大纲、读者反应和编辑意见。
  · 记忆维护员 — 将会看到：批准后的正文、注册表授权给它的资料；不会做：直接改资料，只提交预览。
  如果运行详情里有作者资料包的字符数，在作者浮层补"共 X 字符"，没有就不写。

C. 编辑决定条（岗位链下方一条纸白横条）
- LOCAL_EDIT："编辑决定：局部修改"+"N 处，涉及原稿 X%：a 处事实修正，b 处文学修改"+ 右侧"查看作者原稿"（点击切到修订稿并提示"修订稿里可以逐处看到删改"）。
```
