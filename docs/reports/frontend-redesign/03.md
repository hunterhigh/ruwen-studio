# 块 3 · 章节审稿桌

## 做了什么

- 分支 `feat/frontend-redesign-03` 已变基到包含块 2（PR #44）的 main `0127fe3`。外框、开发横幅和四个项目模式由块 2 提供，章节页保留块 3 的审稿桌与既有资料提交入口。文案保留两边新增键，未发生同键冲突。
- 项目布局持有一份 `useProjectDecisions`，ProjectBar 和审稿桌共享。正文批准、资料批准、退回和放弃成功后立即刷新，异步运行进入或离开待批准状态时再按已保存状态刷新。局部修改为零时显示“编辑通读后没有修改正文”，原稿与正文相同时隐藏原稿按钮。
- 运行列表实查包含 `chapter_run`、`ideation_dispatch`、`ideation_coordinator` 和 `ideation_execution`。构思派发也可能带章节号。共享纯函数 `chapterRuns` 只保留有章号的 `chapter_run`，同时用于历史和起始章号，块 6 可复用。
- 审稿桌有发起对话框、同章运行历史、角色进度与权限浮层、清稿/修订稿、双向定位批注、核验、错误和批准后状态。编辑位置来自 `reports["wenxue-bianji"].output.edits`，旧修改档案只解析成可读列表。批注只由客户端 ref 设置位置，印章、呼吸和光标尊重 reduced motion。
- 正文批准要求结尾和两份核验结论进入视口，各以 60% 为阈值，候选哈希改变时重读。正文和资料批准请求继续发送 `confirmed`、`expectedSha256`、可选 `expectedTargetSha256`，退回发送 `{ reason }`，放弃发送 `{}`。沿用原 CSRF 客户端与服务端接口。已生成资料预览从 `?view=memory` 进入既有文件对比和提交表单。
- 岗位点数按账户用量的 run_id 和 role_id 求和。null 显示待核对，找不到记录引到账户页。批准与完成时间取 `run.events`。
- 改动文件为 `apps/web/src/components/{ChapterStudio,ProjectBar}.tsx`、`components/chapter/{ExistingMemoryReview,Manuscript,ReviewPanels,RunDesk}.tsx`、`components/chapter/{marks,review-data,runs,runs.test}.ts`、`components/project/ProjectDecisions.tsx`、`apps/web/src/app/(studio)/projects/[projectId]/layout.tsx` 及 `chapters/page.tsx`、`apps/web/src/copy/zh-CN.ts`、`apps/web/public/studio.css`、`apps/web/e2e/chapter-review.ts`、`apps/web/e2e/{billing,chapter-review,chapters,ideation-persistence,real-preview,risk-controls,shell,stream-reset}.spec.ts`、`docs/OPEN_QUESTIONS.md`、本报告及 `03/` 截图。
