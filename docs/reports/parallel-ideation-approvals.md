# 构思后端第三批：批准、分派与资料提交

日期：2026-11-10。接续 PR #6、#7，依据契约 v1.1 第 9 节。新增 IdeationWorkflow；createIdeationService 返回其服务。网页路由仍由主线程注册，不修改 apps/web 或 packages/billing。

通讯门批准重新散列平台不可变快照和独立 payload，校验归属、pending、来源及注册表哈希，再建立实际 handoff_execute，消费一次后创建新的四岗任务。任务请求只放 ID；执行每个 provider 请求前重新读取批准凭证、已消费的上游事件、来源、readers 与运行前置门。下游只看到干净委托，不能读取协调员消息或原话快照。

治理、故事使用小节补丁和受限新文件；现有文件必须本次实际读取，base 哈希、唯一标题及预算均由服务端校验。预览的 after 字节与注册表前后记录由服务端计算。用户批准后，文件、resource_activate、注册表、审计账本、平台决定和任务状态同一 PostgresFS 事务提交，失败全部回滚。审批/交接/账本/运行状态/章节路径禁止模型写入。决定凭证不可变，新迁移 0202 绑定任务来源预览的项目/会话复合外键。

学习计划阶段没有搜索工具、不接受证据产出；批准计划才创建调查任务。external_search 未配置 SearchProvider 时返回 SEARCH_UNAVAILABLE，原计划保持 pending。existing_materials 不提供搜索。调查只产出待批 evidence 文件，激活后仍不给作者、故事或编译员读取权限。测试仅用内存 SearchProvider，不配置 key、不真实联网。

只有安全 onDelta 进入事件；下游工具材料和预览另做原话检查，新增文件名也检查，技术 ID 不作为原话快照通道。拒绝理由/修改意见只进协调员消息，修改另起协调员回合；关闭会话拒绝修改。来源变化的预览在列表过滤前标为 stale，避免错误地出现在 pending 页。

衔接主线程 P6：实际 usage 一次结算；待批任务暂留预留，批准/拒绝/修改/取消完成后释放。批准计划时同事务先释放父任务未用额，再报价调查任务，失败回滚父子两端。取消待批任务拒绝其未决定预览，不撤销已批准文件；未知响应崩溃恢复保持 review，不自动再次调用模型。

本批表现产出仍为 proposed 预览，批准明确返回 CLOSURE_AUDIT_REQUIRED；没有伪造六项通过、试写或自动激活，第四批补齐。编译入口也在第四批提供。

验证：17 项真实 Postgres/faux 测试覆盖四岗隔离、单次消费/重复批准、原子文件/注册表/审计失败回滚、闭会话与全决定接口越权、来源过期、受限新文件、搜索两步门及精确余额、取消与两处原生 SIGKILL。pnpm lint、pnpm typecheck、pnpm test 全绿（57 文件、523 测试）；Linux CI 结果见本批 PR。未把类型/假数据当成实现验收。
