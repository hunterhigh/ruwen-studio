日期：2026-11-06。P0 已由用户回复“继续”确认。P1 没有人工闸门，验收后继续 P2。

## 已实现

- ProjectFS、LocalDirFS：原始字节、严格 UTF-8、受限路径、拒绝符号链接/junction、独占创建、项目级进程间锁、嵌套保存点、回滚与事务句柄失效。8 个可复用契约/本地专项测试，P4 可复用契约入口。
- 资源注册表、状态转换、批准 reserve/commit/rollback、技术与文学账本、story state 2.0、作者资料包、交接校验、就绪/治理/闭合审计、项目初始化均移植为 TS；所有项目 IO 经 ProjectFS。
- `packages/core/bin/ruwen-core.ts` 支持本阶段 11 个脚本的 CLI（兼容 Python 下划线脚本名，也支持横线名）。v4.1 目录迁移未提供，state 1.2→2.0 的工程状态迁移已实现。
- 记忆预览与提交接口：预览不动正典；整份预览哈希批准，重新核验文件/注册表版本，在同一事务应用补丁、刷新注册表、审计和状态并消费批准。失败时所有修改和消费标记回滚。
- 从固定上游 Git 对象生成静态模板/规则快照并自动核验；产品核心不调用 Python、Git、子进程或外部模型。Python 只存在于开发与参考验证路径。

## 重要边界

- 新建项目是未就绪脚手架，不是自动批准小说项目。
- 记忆提交只修改已经激活的人物/世界/故事资源，表现能力更新仍要求独立证据与版本流程。
- LocalDirFS 是合作调用者持锁的本地事务模拟。直接读取物理目录的其他程序不受锁约束；强制杀进程后的锁/备份自动恢复尚未验证。生产worker的数据库事务与崩溃恢复在P4。
- 当前验证环境是Windows/Node24/Python3.11；已保留平台输出语义，未宣称Linux部署实测完成。
- 岗位上下文隔离 I4/I5/I6/I7、上游返回和原稿保存 I11/I12 属于P2，租户归属API I13属于P5；本阶段不宣称这些已被产品接线。
