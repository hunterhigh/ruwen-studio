## 已交付

- Drizzle业务schema、首个SQL迁移与迁移完整性检查：项目文件/历史、批准索引、运行/步骤、岗位/提示词、构思消息/预览，以及后续认证、额度和支付的基础表。
- PostgresFS复用ProjectFS契约；原始字节、数据库生成哈希、独占创建、嵌套保存点、事务失效保护、项目归属检查、历史回滚。
- pg-boss worker和可事务入队服务：章节、两次人工批准、记忆生成、取消；构思四岗位的已批准干净委托，以及用户显式发起的情境编译。构思产出只生成pending预览，不改正典。
- 持久化岗位结果、提示词去重、实际报告用量和唯一费用事实。SQL检查点与文件/批准消费原子提交，LISTEN/NOTIFY进度只发送标识和状态。
- ZIP导出/导入与受限验证；原始批准证据在复制到其他目录或数据库后仍可通过就绪检查。
- compose.yaml、无Docker本地Postgres入口、数据库演示入队脚本和后台worker入口。运行方法见docs/persistence.md。

## 验证

`pnpm lint`、`pnpm typecheck`、`pnpm test`全部通过：20个测试文件，213个Vitest用例，包括原始Python36项基线和严格差分。

| 验证 | 结果 |
|---|---|
| LocalDirFS / PostgresFS共享契约 | 两者通过；Postgres另验证归属、历史、账本不可改写和Drizzle/迁移字段一致 |
| 真实pg-boss全链 | 发起→候选稿待批→人工批准→记忆待批→人工批准→DONE，6份唯一岗位费用记录；重投不增加 |
| 构思后台任务 | 4岗位已批准委托和独立情境编译通过；预览不改变正式资料/已批准情境；未批准和跨项目委托拒绝 |
| 进程中断 | 14个章节状态事务内SIGKILL，重启处理同一任务后继续；批准消费不重复，记忆写入与协调原子回滚/提交 |
| 结果保存中断 | 6岗位分别在结果已提交时SIGKILL，重启后复用结果 |
| 外部结果未知 | 作者/记忆响应尚未保存时SIGKILL，恢复停止且不自动重发，费用保留未知 |
| 队列自身恢复 | 真实pg-boss心跳过期后将失联worker任务投递给新worker，复用已保存作者结果 |
| ZIP往返 | 49份演示文件及额外二进制文件逐文件sha256一致；就绪检查仍通过；9项恶意路径/冲突/链接/校验测试通过 |

本机实际使用Windows上的真实Postgres（embedded-postgres固定18.6.0-beta.19包）；没有用内存SQL模拟器。Docker Compose路径已提供，当前机器无Docker，未声称容器启动实测通过。

## 保留的边界

模型请求与数据库不是同一事务。未落盘的服务商响应不能自动判断是否收费，此分支明确停待核对；不承诺真实服务商请求恰好一次。213项测试使用faux，不验证文学质量、真实API成本或额度扣款。

P5的认证、网页/API、SSE客户端和完整构思预览提交UI尚未实现；P6付费未启用。文件系统层归属检查不能替代P5的登录/项目所有权中间件。LocalDirFS强制终止后的自动恢复仍沿用P1边界，生产恢复由数据库实现。
