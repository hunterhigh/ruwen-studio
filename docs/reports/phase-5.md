### §3.3第4条响应头逐项对照

| 设计要求 | 实际策略 | 验证 |
|---|---|---|
| default-src 'self' | 相同 | security.test、生产浏览器 |
| img-src 'self' data: | img-src 'self'，保留更严格策略，省略data:；用户图片在组件层全部替代为文字 | ADR-009记录此更严格差异；恶意图片无请求 |
| connect-src 'self' | 生产相同；仅开发模式额外允许本机wss热更新 | 生产浏览器CSP无违规；没有为开发工具开启unsafe-inline |
| frame-ancestors/base-uri/form-action | 分别为none/none/self，相同 | security.test逐条检查 |
| 脚本nonce | 逐请求随机nonce；生产不启用unsafe-inline/unsafe-eval | 实际生产页面脚本运行且无CSP违规 |
| HSTS / nosniff | HSTS max-age=31536000; includeSubDomains；nosniff | 单元及实际HTTPS响应 |
| Referrer-Policy | 已与设计对齐为strict-origin-when-cross-origin | 单元断言及浏览器响应 |

另保留style/font同源、object-src none、X-Frame-Options DENY、权限与COOP/CORP保护。内容策略不按小说关键词拒绝；没有改动上游提示词或I1–I13。

配置对照由config/runtime.json提供并标注待P3实测：每用户2章并发、每项目1、协调员每会话每小时60轮、每天套餐点数30%、试用目标1～2章。协调员8000字上限读取现有securityLimits。

### 安全文本事件链路（本轮第3项）

唯一正文流路径为provider → runRole/RoleSecurity → 安全层释放的onDelta → WorkerService.streamSink → web_run_events → 已鉴权SSE。worker没有订阅原始模型事件，SSE没有从原始输出、thinking或transcript补发文字的旁路；调用点、落盘入口和重放查询均已补明确约束注释。

新增approved-stream.test.ts使用真实岗位安全层、worker、Postgres和API路由的SSE响应体：假provider发送正常前缀、thinking/签名和会被拦截的尾部，并在完成消息前暂停。测试先确认正常前缀已落盘且实时SSE与其一致，随后释放消息并确认岗位失败；失败没有追加暂扣尾部，重连回放仍与原安全帧一致。原始标记、thinking和签名均未进入文本事件或SSE。已放行的安全前缀可以在失败前显示；这不等于候选稿已批准。后续尝试重置事件接入时仍须保留这条安全边界。
