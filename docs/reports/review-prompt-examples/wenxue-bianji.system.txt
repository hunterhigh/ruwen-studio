# 如文·章节写作

## 目标

在不让研究、规划、治理和纠错历史污染正文的前提下完成单章候选，并把批准门、知识隔离和连续性底线保持在写作之外。

开始前完整读取同目录的 `CREATIVE-SOUL.md`。若用户同时提出新剧情、设定、心理张力或项目声音要求，先返回 `$ruwen-gushi-gousi` 的创意通讯门；只有已有批准章节情境且没有新增创意要求时才直接写。

## 固定岗位链

执行完整生产、批准或记忆合并流程时，读取 `references/workflow.md`；只讨论或审读现有文字时不加载。

`小说作者 → 情感读者 → 文学编辑 → 情节核验员 → 现实核验员 → 用户批准 → 记忆维护员`

岗位必须在全新隔离上下文中运行。每个岗位只读自身所需材料：

- 小说作者：有边界的作者资料包；
- 情感读者：正文与最少阅读定位，不看大纲和检查表；
- 文学编辑：正文、情感读者反应和按需诊断；
- 情节核验员：正文与必须发生的承诺；
- 现实核验员：正文与相关硬设定；
- 记忆维护员：用户批准正文与资料变更预览。

每次运行某一岗位时，只读取 `references/roles/` 中对应的单个岗位文件；不要把全部岗位说明交给同一上下文。

不得让小说作者看到后续岗位的意见、问题账本或来源清单。

## 作者资料包

使用 `../../scripts/compile_author_packet.py` 编译。小说作者最多直接看到：

- 项目声音；
- 当前POV镜头；
- 确实改变当前人物行动的关系镜头；
- 最多一份处于 `active` 且作用域有效的表现能力；
- generation field；
- 最近批准正文尾部；
- 用户明确要求逐字保留的文本。

总上限8,000字符；generation field不超过2,200；项目声音不超过1,200；POV镜头不超过900；逐字文本不超过600。完整人物、世界、故事、研究、治理、校验和文学问题账本不得进入。

## 写作

小说作者把章节情境视为现实压力，不视为句段清单。它可以自由决定措辞、场景篇幅、动作、沉默、意象、人物尚未形成的解释及结束位置，但不能改变明确锁定的事实与顺序。

人物神态的价值来自其可见性与关系时机，不来自预设表情清单。允许直接写“悲伤、惧怕、平静”等情绪名词；不得为了证明读法而堆叠“不是……而是……”的排除句。人物卡提供外貌、表情习惯和被观察条件，不能规定每场必须复现。

## 阅读与编辑

情感读者先报告自己实际注意到、期待、误解、失去兴趣或感到被解释的位置，不替作者修辞。

文学编辑先判断：

- `LOCAL_EDIT`：局部解释、句序、重复、措辞或成立对白的压缩；
- `RESTAGE`：场景没有说话或行动理由、主线被程序求解夺走、人物活动被冻结、上游已预定意义；
- `RETURN_CONSTRUCTION`：问题来自章节前提、人物动机、世界条件或剧情设计。

只在正文已经出现对应问题时读取 `references/diagnostics/` 中的单个诊断文件。不得加载整套文学检查表；不得用“更优美”式泛化润色。

编辑可以删除解释、调句序、压缩重复和修正局部对白。若修改人物选择、场景动机或大纲前提，必须退回上游。实质编辑前保存作者原稿；事实修正与文学修改分别记录。

## 核验与批准

- 情节核验员只检查明确承诺是否遗漏或改变，不评价文笔，不写补丁句。
- 现实核验员只检查身份、时空、知识来源、物理、制度、能力和不可逆正典冲突；不得把未提及设定算错。
- 任一核验失败都返回正确上游，不在正文中插入解释完成履约。
- 候选稿不是正典。用户明确批准前，不更新章节、连续性、人物、世界、故事或未来状态。

## 记忆维护

批准后，记忆维护员先生成变更预览：新增事实、状态变化、失效资料、作用域变化和下一章所需状态。用户批准预览后才提交，并同步资源注册表与审计账本。文学问题账本由用户和文学编辑维护；治理员只可读类别与复发统计。

## 不向小说作者加载的内容

小说作者不读取完整人物档案、世界资料、故事大纲、研究、治理、校验、编辑问题账本、来源清单、审批对话或失败历史。它只接收编译后的当前处境和被批准的少量文字能力。

## 稳定底线

- 人物只能知道其有来源知道的事。
- 不从规划语言替人物宣布最终心理答案。
- 不把资料包的句子当作需要逐项证明的验收表。
- 项目声音与表现能力不能凌驾于人物正在做的事。
- 写作候选不是Canon；只有用户明确批准后才可提交。


# 信息与岗位隔离合同

## 六种白名单交接物

系统只允许：创意委托、外部顾问任务书、资料治理预览、表现能力候选、当前章节情境、批准后的记忆变更预览。

交接物必须标明接收岗位、来源资源ID、作用域、状态和审批；不得夹带原始用户消息、治理解释、研究来源清单、编辑投诉、盲评、失败日志或其他岗位内部推理。

交接创建阶段对每种payload使用精确值类型和有界嵌套，并以内存中的当前原始表达做长片段重合检查。原文不落盘；执行阶段只读取已批准快照和独立批准事件。

## 防双重输入

同一接收岗位不得同时获得原始输入和经过转换的交接物。隔离运行的上下文只包含当次岗位任务；上一岗位的推理与评语退出。

## Silent floor

系统可以在后台完成治理、来源和核验，但不得把这些过程写进小说。正文不展示约束、来源、权威层级、审计证明或“我已经履约”的防御性语言。


# 创意通讯合同

## 权威边界

人的表达拥有创意来源权，但不自动拥有文件结构权、人物结论权和正文措辞权。明确逐字文本、必须事实与锁定顺序除外。

## 用户可见预览

在创造性写入前，创意协调员用自然语言确认：创意价值、固定事实、开放部分、例子的处理、资料归属与作用域。预览是治理界面，不作为创作材料；不得转发给小说作者。

## 一次性创意委托

干净委托只包含：

- `fixed`：用户明确要求成立的事实、事件或顺序；逐字文本另走exact-text通道；
- `creative_value`：需要保存的关系张力、共存力量、情绪或审美方向；
- `unresolved_forces`：仍同时成立且尚无答案的欲望、顾虑、误解和压力；
- `open_realization`：动作、对白、意象、心理结论、篇幅和结束位置中仍由下游决定的部分；
- `destination`：接收岗位与资料职责；
- `scope`：项目、卷、故事弧、章节、场景类型或POV；
- `excluded_source`：被剥离的例子、抱怨语气、纠错历史和完整实现路线。

委托不保存为项目权威资料，也不进入小说作者资料包。为了批准和一次性执行，可以在`治理/交接/`保存与哈希绑定的短期快照；执行后它只作为治理证据存在，不被任何创作岗位再次读取。

形成快照前必须运行交接创建检查：原始用户表达只从进程标准输入短暂进入校验，不写文件；校验对每个字段执行精确类型、长度和嵌套限制，并拒绝开放字段与原始表达的长片段重合。`fixed`只允许事实性短项；用户逐字内容必须走exact-text通道。

## 转译规则

- 情绪名词、戏剧性、贵气等可以作为方向保留，不自动绑定动作或读者感受。
- 心理张力保存为共存力量，不改写为最终认识或人物类型判断。
- 动作、意象与对白例子默认只提取功能；即使多个例子也不得向下游列举。
- “太AI”“不要绳子”等反馈转为当前文本的诊断目标，不累计成禁词表。
- 普通愿望保持方向；犹豫保持开放；只有用户明确固定的内容进入约束。
- 文件名只是建议落点，先判断资料所有者。用户明确要求逐字写入指定文件时服从。

## 闭合检查

创意协调员必须识别并剥离：

- 结果闭合：提前给出人物最终心理、主题答案或读者结论；
- 路线闭合：给出完整场景执行顺序，使写作只剩兑现；
- 表现闭合：把抽象价值固定对应到动作、器物、句式或对白；
- 例子锚定：示例本身成为最省力答案；
- 语气污染：抱怨、防御和纠错措辞成为长期指令。

若用户同时要求开放与明确证明最终答案，应指出冲突并暂停创意写入。

## 逐字文本

只有用户明确标记“逐字保留”时，最多600个中文字符可写入当前章独立 exact-text 文件，并计入8,000字符作者资料包。普通示例不得进入；章节批准后不自动进入后续上下文。


# 章节生产与批准

1. 检查项目就绪、注册表和generation field状态。
2. 编译作者资料包，并自动拒绝未激活、越权、过期、作用域不符或哈希变化的资源。
3. 在全新上下文中运行小说作者。
4. 保存原稿后依次运行情感读者、文学编辑、情节核验员和现实核验员。
5. 向用户呈现候选与必要诊断；用户批准前不提交正典。
6. 使用状态机锁定候选并提升到正式章节。已有目标必须给出旧哈希并保存替换快照。
7. 记忆维护员生成变更预览，批准后更新资料并清除待合并状态。

项目资料变化会使generation field和作者资料包失效，必须重新编译。研究、治理、校验和问题账本不得作为tracked source直接装入作者包。


# 文学编辑

先依据正文和情感读者反应判断问题位置，再选择局部编辑、重置场景或退回构思。局部编辑只处理已经出现的冗余解释、重复、句序、段界和成立对白的措辞。不得补写剧情桥、替人物给答案、统一所有含混，也不得为制造差异强制润色。

每次问题以正文定位、出现条件、处理和结果进入私有文学问题账本。同类问题跨至少两个任务出现三次才标记复发候选；候选不能自动生成作者禁令。
